# 📄 Product Requirements Document (PRD)
## Project: **Instill**
**Stage:** MVP (Single-user, high-quality learning loop)  
**Owner:** You  
**Platforms:** Web (Responsive → Desktop & Mobile browsers)

---

## 1. Product Summary

### One-Sentence Description
**Instill** is a learning mastery system that transforms passive reading into verified understanding through adaptive assessments, enforced progression, and long-term retention tracking.

---

### Problem Statement
People read books and consume educational content without retaining or being able to apply what they learn. Existing tools optimize for *completion*, not *comprehension*, leading to:

- Illusion of competence  
- Rapid forgetting  
- No feedback loop for understanding  

---

### Solution
Instill enforces real learning by introducing:

- Segment-gated progression  
- Adaptive, concept-level assessments  
- Spaced recall of earlier material  
- Strength & weakness summaries  
- A final personal understanding report  

---

## 2. Goals & Non-Goals

### MVP Goals (Must-Have)
- Convert a long-form learning source into a mastery-enforced experience
- Prove that users *feel* the difference between “finished” and “understood”
- Deliver accurate **strengths & weaknesses summaries**
- Work seamlessly on **web, desktop, and mobile browsers**
- Validate LLM-generated assessments as a core differentiator

---

### Explicit Non-Goals (MVP)
- Multi-user or social features
- Monetization
- Native mobile apps
- Offline mode
- Video or audio sources (planned later)
- Notes, highlighting, or flashcards

---

## 3. Target User (MVP)

### Primary User
- Technical or analytical learner
- Reads difficult or high-signal books
- Will tolerate friction if it improves understanding
- Self-directed learner

> The MVP is explicitly designed for **a single power user** (you).

---

## 4. Supported Learning Sources (MVP Scope)

### MVP Source Type
✅ **Books (PDF only)**  

### Deferred (Architecturally Anticipated)
- Video lectures (YouTube, uploaded video)
- Courses
- Papers / documentation

## 5. Core User Flow (MVP)

### 5.1 Onboarding
1. User opens Instill
2. Short explanation of the “mastery contract”
3. User uploads a PDF book

---

### 5.2 Book Processing
System:
- Extracts text from PDF
- Detects chapters
- Builds an internal **concept model**

User:
- Sees chapter list
- Chapter 1 unlocked
- All other chapters locked

---

### 5.3 Reading & Mastery Loop
For each chapter:

1. User reads the chapter
2. User clicks **“I’m Ready to Continue”**
3. Mastery assessment begins
4. User must reach mastery threshold (default: 90%)
5. On success:
   - Chapter marked **Mastered**
   - Next chapter unlocks
6. On failure:
   - Immediate feedback
   - Retry allowed after review

---

### 5.4 Continuous Recall
As progress continues:
- Earlier chapters reappear with **1–3 recall questions**
- Triggered by:
  - Time elapsed
  - Prior weakness
  - Concept importance

---

### 5.5 Completion
When the final chapter is mastered:
- Instill generates a **Personal Understanding Summary**
- Strengths, weaknesses, and decay risks are presented

---

## 6. Functional Requirements

---

### 6.1 Book Upload
- Accept PDF files
- Explicit size limits
- Clear error handling for unreadable PDFs

---

### 6.2 Chapter Detection
- Automatic chapter segmentation
- Manual override for edge cases
- Display chapter titles and estimated length

---

### 6.3 Assessment Generation (Critical Requirement)

#### Specialized LLM Requirement
All quizzes and assessments must be generated by a **specialized LLM** whose sole responsibility is **learning assessment generation**.

This LLM must:
- Be provided with chapter text and concept structure
- Generate **non-trivial questions**
- Avoid rote memorization
- Prefer reasoning, explanation, and application
- Generate answer keys and evaluation criteria

> Question generation is **not** a generic LLM call.  
> It is a dedicated assessment agent.

---

### 6.4 Assessment Types (MVP)
- Concept explanation (“Explain X in your own words”)
- Distinction / comparison
- Application scenario
- Misconception detection (light)

Each chapter:
- 5–10 questions
- One question shown at a time
- Partial credit supported

---

### 6.5 Adaptive Logic (MVP-Light)
- Track incorrect answers by concept
- Re-ask missed concepts using rephrased questions
- Increase difficulty on success
- Reduce scope on repeated failure

---

### 6.6 Strength & Weakness Tracking
For each concept:
- Mastery state: Strong / Moderate / Weak
- Last successful recall timestamp
- Failure count

Aggregated into:
- Chapter-level summaries
- Book-level summaries

---

### 6.7 Spaced Recall (Simple MVP)
- Inject 1–3 questions from earlier chapters
- Triggered every N chapters
- Prefer weak or unstable concepts

---

### 6.8 Personal Understanding Summary
Generated when the book is completed:

Includes:
- Concepts strongly understood
- Persistent weak areas
- Concepts likely to decay
- Suggested review priorities

This summary must feel **personal and accurate**, not generic.

## 7. UX / UI Requirements

---

### 7.1 Platform Strategy
- Single responsive web application
- Desktop-first
- Fully usable on mobile browsers
- Touch-friendly
- No native apps in MVP

---

### 7.2 Key Screens (MVP)

1. **Landing / Upload**
2. **Book Overview**
   - Chapter list
   - Locked / unlocked indicators
3. **Reading View**
   - Chapter text
   - Progress indicator
   - “Ready for Assessment” CTA
4. **Assessment View**
   - One question at a time
   - Immediate feedback
5. **Progress Dashboard**
   - Strength vs weakness overview
6. **Completion Summary**

---

### 7.3 UX Principles
- Calm, serious tone
- No gamification fluff
- Friction is intentional
- User always understands *why* they’re being tested

## 9. Technical Constraints & Preferences

### Preferred Stack
**Frontend**
- React
- TypeScript
- Responsive-first design

**Backend**
- Python (API + orchestration)
- Async-friendly
- Stateless where possible

**LLM Layer**
- Dedicated assessment-generation model
- Prompted with:
  - Chapter text
  - Concept breakdown
  - Prior failure data

**Optional / Future**
- C++ for performance-critical components only
- Desktop wrapper via web container

---

## 10. Success Metrics (MVP)

### Qualitative
- Does Instill expose misunderstandings?
- Does it feel meaningfully different from just reading?
- Is the final summary accurate and insightful?

---

### Quantitative
- Chapter pass rate
- Retry frequency
- Concept stability over time

---

## 11. Risks & Mitigations

### Risk: Poor Question Quality
**Mitigation**
- Fewer questions
- Higher quality
- Manual inspection during MVP

---

### Risk: Excessive Friction
**Mitigation**
- Adjustable mastery threshold
- Clear feedback
- Unlimited retries

---

### Risk: Scope Creep
**Mitigation**
- Books only
- Single user
- No accounts initially

---

## 12. MVP Definition of “Done”

Instill MVP is complete when:
- A user can upload a PDF
- Progress is gated by mastery
- Assessments are meaningfully challenging
- Weaknesses are surfaced clearly
- A personal understanding summary is generated
- The user wants to use it again

---

## 13. Recommended Build Order

1. PDF ingestion + chapter detection
2. Reading + assessment UI loop
3. LLM-based assessment generation
4. Concept-level tracking
5. Spaced recall
6. Completion summary generation

---

## Final Note

**Instill is not about learning more.**

It is about finally knowing **when learning has actually happened**.
